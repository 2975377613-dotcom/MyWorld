# MyWorld

> 一个兼具审美表达、个人效率与 AI 能力的个人数字入口网站  
> A personal AI-native portal for navigation, search, and intelligent workflow.

---

## 1. 项目简介

**MyWorld** 是一个面向个人使用、后续可公开访问的综合型网站项目。  
它不是传统博客，也不是普通网址收藏页，而是一个融合了以下能力的个人数字中枢：

- 常用网站导航
- 聚合搜索入口
- AI 对话与辅助工作台
- 收藏、历史与个性化设置
- 具有强视觉风格与品牌感的首页体验

项目的核心目标是：  
**把“打开浏览器后要做的第一件事”统一收拢到同一个高审美、高效率、高扩展性的网站中。**

---

## 2. 项目定位

MyWorld 的定位不是“做一个搜索引擎”，而是：

**一个个人化的 AI 导航门户 / 搜索工作台 / 数字控制台**

它的价值在于：

1. 把我常用的网站整合为统一入口
2. 把搜索、跳转、提问、总结等行为集中到一个界面中
3. 把原本零散的网页工具使用流程，变成一套统一的交互体验
4. 在实用性的基础上，追求新颖、有创意、富有审美的视觉表达

---

## 3. 项目愿景

我希望 MyWorld 最终成为一个：

- **打开即用** 的个人主页
- **视觉上有辨识度** 的品牌化网站
- **功能上具有实用价值** 的工具型入口
- **结构上便于持续扩展** 的长期项目

未来它不仅可以作为我自己的浏览器首页、个人工作台，也可以作为一个公开访问的网站，展示我的审美、想法与个人数字空间。

## 7. 设计方向与审美目标

### 7.1 设计总方向

MyWorld 不走传统工具站的“纯功能白底网页”风格，而是走：

**未来感 / 工业感 / 科幻感 / 轻二次元品牌感 / 数字终端感**

整体目标不是“花哨”，而是：

- 有氛围
- 有质感
- 有统一语言
- 有可识别的视觉品牌

### 7.2 视觉气质关键词

- 深色基底
- 冷色调为主
- 单一高亮强调色
- 半透明面板
- 分层空间感
- 控制台式布局
- 细腻微动效
- 少量 3D / 粒子 / 光效点缀
- 首页具有“进入系统”的仪式感

### 7.3 参考风格方向

本项目可借鉴的不是单一网页，而是一类风格：

- 工业科幻 UI
- 高品质游戏官网的沉浸式首屏
- 强交互、强氛围的品牌展示页
- 有层次、有镜头感的动态页面
- 具有系统面板感的功能布局

### 7.4 设计原则

1. **视觉统一高于元素堆砌**
2. **氛围表达不能牺牲可用性**
3. **首页可以强风格，但功能区必须清晰**
4. **动画应服务于体验，而不是喧宾夺主**
5. **参考不等于照搬，必须形成自己的语言**

## 8. 产品形态

MyWorld 的最终形态不是单页宣传站，而是一个可持续使用的网站系统。

建议包含以下页面或区域：

### 8.1 首页 Home
首页应承担以下职责：

- 展示网站气质
- 提供统一入口
- 呈现核心搜索框
- 呈现快捷导航
- 呈现 AI 工作台入口
- 建立“这是我的数字世界”的整体感受

### 8.2 导航区 Navigation
用于放置我最常访问的网站，支持：

- 分类分组
- 图标化展示
- 收藏排序
- 快速跳转
- 自定义增删改

建议分类如：

- 开发
- 学习
- 工具
- AI
- 社交
- 娱乐
- 个人常用

### 8.3 聚合搜索区 Search
统一搜索框是本项目的重要核心。

输入一段内容后，用户可选择不同模式：

- 网页搜索
- AI 解答
- 网站直达
- 站内搜索（未来）
- 图片/学术等扩展搜索（未来）

### 8.4 AI 工作区 AI Workspace
AI 区域用于接收问题并返回结果，后期可扩展为多模型切换。

第一阶段建议实现：

- 输入问题
- 获取回答
- 展示结果
- 支持继续追问
- 支持总结提炼

后续可扩展：

- 模型切换
- 多轮上下文
- 结果引用
- 历史会话
- Prompt 模板
- 结果收藏

### 8.5 收藏与历史区域
用于保存：

- 常用网站
- 搜索历史
- AI 对话历史
- 常用指令
- 最近访问内容

### 8.6 设置页 Settings
用于管理：

- 默认搜索方式
- 默认 AI 模型
- 主题样式
- 动效强度
- 导航分组
- 首页布局偏好

## 11. 技术路线建议

### 11.1 总体路线

建议采用：

- **Next.js**
- **TypeScript**
- **Tailwind CSS**
- **shadcn/ui**
- **Motion**
- 视情况加入少量 **Three.js / React Three Fiber**
- 本地数据优先使用 `localStorage`
- 后期再引入数据库与用户系统

### 11.2 为什么这样选

因为本项目既有前端页面需求，也有接口需求：

- 前端需要高质量 UI
- 后端需要代理 AI / 搜索请求
- 页面需要较好的组件化能力
- 后续还要考虑公开部署和扩展

因此采用统一的全栈 React 路线更合适。

### 11.3 第一阶段技术原则

- 优先保证结构清晰
- 优先保证组件可复用
- 优先保证页面可维护
- 不为了炫技牺牲性能与开发效率
- 重视觉，但不滥用动画

本项目明确采用：

**先本地开发，再公开部署**

- 搭 UI

当本地版本成熟后，再部署到线上平台，供公开访问。

建议顺序：

1. 本地开发完成
2. 部署到线上平台默认域名
3. 测试稳定性与访问体验
4. 需要时再绑定自定义域名

### 15.3 当前决策
本项目当前不做“半私密访问”方案，路线明确为：

- 本地开发
- 后续公开

## 17. 环境变量设计（建议）

如果后续接入 AI 或搜索接口，建议使用环境变量管理敏感信息。

可预留如下变量名：

```bash
NEXT_PUBLIC_APP_NAME=MyWorld
OPENAI_API_KEY=
SEARCH_API_KEY=
SEARCH_API_BASE_URL=
```

说明：

- 所有密钥必须放在服务端使用
- 不要把敏感 key 直接写进前端代码中
- 前端应调用项目自己的接口，再由服务端去请求外部服务

## 24. 给 Codex 的开发说明

如果由 Codex 或其他 AI 编程助手参与开发，应遵守以下原则：

- 以本 README 为项目方向说明

- 先搭首页和基础布局
