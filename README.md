# MyWorld

> 面向 MVP 开发的产品规范  
> Development-first product spec for the first usable version

---

## 1. 文档目的

本 README 的用途是指导 **MyWorld MVP** 的设计与开发，不再承担品牌宣言、灵感收集或长期蓝图的主要角色。

阅读本文件后，开发者应能直接回答以下问题：

- 第一阶段到底做什么，不做什么
- 首页和核心模块各自承担什么职责
- 搜索、导航、AI 的最小闭环如何定义
- 本地数据应以什么对象结构保存
- 什么状态算 MVP 完成

---

## 2. 项目定义

**MyWorld** 是一个个人使用优先的数字入口网站，用来统一承接打开浏览器后的首批动作：

- 访问常用网站
- 发起搜索
- 提问 AI
- 读取少量个人偏好与历史

它不是博客，不是完整聊天产品，也不是搜索引擎。  
第一阶段的目标是做出一个 **本地可运行、视觉统一、交互顺畅、可持续扩展** 的个人入口。

---

## 3. MVP 定义

### 3.1 MVP 目标

MVP 只交付 4 个核心闭环：

1. 首页框架与统一视觉基调
2. 导航卡片区
3. 统一搜索框
4. 基础 AI 面板

以下能力只保留最低限度支持，不单独扩展成完整系统：

- 收藏
- 历史
- 设置

### 3.2 MVP 成功标准

MVP 完成后，用户应能在一个页面内完成这些动作：

- 一眼看到核心搜索入口
- 快速点击常用网站跳转
- 在网页搜索、AI 提问、直达跳转之间切换
- 输入问题并获得基础 AI 回复
- 刷新页面后保留必要偏好和轻量历史

### 3.3 当前非目标

以下内容明确不属于第一阶段：

- 账号系统
- 云端同步
- 多人协作
- 复杂搜索聚合编排
- 多模型管理系统
- 浏览器扩展
- 重型数据库
- 大型 3D 场景
- 推荐算法
- 后台管理系统

## 4. 目标用户与使用场景

### 4.1 当前目标用户

- 项目作者本人

### 4.2 典型使用场景

#### 场景 A：打开浏览器后的第一步

用户打开首页后，优先看到搜索框和常用入口，不需要进入多个站点再开始工作。

#### 场景 B：快速访问常用工具

用户通过导航卡片进入 GitHub、Notion、ChatGPT、邮箱等常用网站，不依赖浏览器收藏夹层级。

#### 场景 C：直接提问 AI

用户在同一入口输入问题并获得回答，不跳到另一个独立聊天产品才能继续工作。

#### 场景 D：保持个人使用习惯

用户刷新或再次打开页面时，仍能看到自己的默认搜索模式、导航顺序和基础偏好。

## 5. 产品结构

### 5.1 页面策略

第一阶段默认以 **单首页承载主要能力**，不强依赖多页面流转。

可保留这些页面或路由能力，但不要求首版全部做完整独立页：

- `/` 首页
- `/settings` 设置页或设置面板
- `/api/chat` AI 服务端代理接口
- `/api/search` 搜索服务端代理接口（仅当需要代理时）

### 5.2 首页信息架构

首页至少包含以下区域，按重要性排序：

1. 顶部品牌区或轻量导航区
2. Hero / 首屏氛围区
3. 统一搜索输入区
4. 导航卡片区
5. AI 面板区
6. 轻量设置入口

### 5.3 首页职责

首页负责：

- 承载统一入口
- 提供清晰的主操作路径
- 展示稳定的视觉基调
- 容纳首版导航、搜索、AI 三个核心能力

首页不负责：

- 完整搜索结果门户
- 复杂会话管理中心
- 高密度后台式设置系统

---

## 6. 视觉与交互约束

### 6.1 视觉目标

首版视觉必须有辨识度，但实现方式要可控。  
禁止使用“未来感”“高级感”这类无法落地的抽象要求代替具体规范。

### 6.2 首版视觉约束

- 深色背景为主
- 仅保留 1 个主强调色
- 面板层级控制在 2 到 3 层
- 统一圆角、描边、阴影和透明度规则
- 动效以轻量过渡和局部进入动画为主
- 不依赖 Three.js 或大型粒子系统完成视觉表达

### 6.3 交互原则

- 搜索框必须是首屏主焦点之一
- 所有核心操作支持键盘优先使用
- 反馈必须清晰，包含加载、空状态、错误状态
- 动画服务于理解层级，不制造干扰
- 移动端至少能完成浏览、搜索、跳转、提问

## 7. 功能规格

本节对每个模块只回答三个问题：

- 做什么
- 不做什么
- 如何验收

### 7.1 首页框架

#### 做什么

- 提供完整首屏布局
- 容纳搜索、导航、AI 三个主模块
- 提供品牌标题、简短说明和视觉氛围
- 保证桌面端优先且移动端可用

#### 不做什么

- 不做内容型长首页
- 不做多段营销叙事
- 不把首页做成纯展示页

#### 验收点

- 首屏可直接发起搜索或提问
- 核心模块在桌面端一屏内可感知
- 布局在手机端不崩坏，关键操作可触达

### 7.2 导航卡片区

#### 做什么

- 展示常用网站卡片
- 支持按分类分组
- 支持快速跳转
- 支持基础置顶或固定能力
- 支持最小必要的本地增删改

#### 不做什么

- 不做复杂标签系统
- 不做共享收藏
- 不做推荐或自动排序算法

#### 验收点

- 默认数据可正常展示
- 用户可新增至少一个导航项并持久化
- 分类结构清晰，不超过必要复杂度

### 7.3 统一搜索框

#### 做什么

- 提供单一输入入口
- 支持模式切换：`web | ai | direct`
- 支持回车提交
- 支持键盘切换模式
- 记录轻量搜索历史

#### 输入与行为规则

- `web`：将输入内容交给默认网页搜索引擎
- `ai`：将输入内容提交到 `/api/chat`
- `direct`：按导航数据做直达匹配；命中时直接跳转，未命中时回退到 `web`

首版不做复杂自然语言分流。  
是否智能识别模式，不在 MVP 范围内。

#### 不做什么

- 不做多搜索引擎复杂聚合
- 不做搜索结果聚合排序
- 不做站内全文检索
- 不做学术、图片、视频等高级搜索模式

#### 验收点

- 用户能明确看到当前搜索模式
- 3 种模式均可触发正确行为
- `direct` 未命中时有稳定回退逻辑

### 7.4 AI 面板

#### 做什么

- 接收问题输入
- 展示回答内容
- 展示加载状态与错误状态
- 支持在当前上下文继续追问
- 支持复制回答内容

#### 最小会话策略

- 首版只要求单会话上下文
- 当前打开页面内支持连续提问
- 是否跨刷新保留完整对话历史，可降级为只保留最近若干条

#### 不做什么

- 不做多模型切换
- 不做 Prompt 模板系统
- 不做引用溯源 UI
- 不做复杂历史管理页
- 不做上传文件、多模态等扩展输入

#### 验收点

- 输入问题后可以得到响应
- 加载态和失败态可见
- 至少支持一次继续追问
- 回复区域具备基础可读性

### 7.5 设置与偏好

#### 做什么

- 管理默认搜索模式
- 管理默认搜索引擎
- 管理动效强度
- 管理布局密度或视觉偏好中的少量必要选项

#### 不做什么

- 不做大型设置中心
- 不做账号、安全、权限设置
- 不做复杂主题编辑器

#### 验收点

- 设置项数量有限且含义清楚
- 修改后刷新页面仍生效
- 设置不会破坏页面整体风格

### 7.6 历史与本地存储

#### 做什么

- 保存轻量搜索历史
- 保存导航数据
- 保存基础 UI 偏好
- 按需保存最近会话片段

#### 不做什么

- 不做跨设备同步
- 不做长期归档系统
- 不做复杂筛选和回溯能力

#### 验收点

- 刷新页面后关键偏好不丢失
- 导航增删改与搜索历史可恢复
- 本地数据结构稳定，不依赖临时字段

## 8. 数据与状态边界

首版采用浏览器本地存储优先策略。  
本地只保存必要偏好与轻量数据，不在前端保存任何敏感密钥。

### 8.1 核心类型

```ts
type SearchMode = "web" | "ai" | "direct";

type NavigationItem = {
  id: string;
  title: string;
  url: string;
  category: string;
  icon: string;
  pinned: boolean;
};

type SearchPreference = {
  defaultMode: SearchMode;
  preferredEngine: string;
};

type SearchHistoryItem = {
  id: string;
  query: string;
  mode: SearchMode;
  timestamp: string;
};

type ChatMessage = {
  id: string;
  role: "user" | "assistant";
  content: string;
  timestamp: string;
};

type ChatSession = {
  id: string;
  messages: ChatMessage[];
  updatedAt: string;
};

type UISettings = {
  themeVariant: string;
  motionLevel: "off" | "low" | "normal";
  layoutDensity: "compact" | "comfortable";
};
```

### 8.2 本地存储范围

允许保存在 `localStorage` 的内容：

- 导航项
- 搜索偏好
- 搜索历史
- UI 设置
- 最近会话片段

不允许保存在前端的内容：

- API 密钥
- 服务端凭证
- 不必要的原始敏感请求信息

### 8.3 状态管理原则

- 首版优先使用组件状态与轻量本地存储封装
- 不预设必须引入复杂全局状态库
- 所有持久化对象应有稳定字段名，避免 UI 命名和存储命名混用

---

## 9. 接口与模块边界

### 9.1 搜索边界

- 前端统一接收用户输入
- `web` 模式由前端生成搜索跳转或请求本项目代理接口
- `direct` 模式只依赖本地导航数据做命中判断
- 若后续搜索需要隐藏密钥，再通过 `/api/search` 代理

### 9.2 AI 边界

- 前端只调用项目自己的 `/api/chat`
- 外部 AI 提供商的密钥仅在服务端使用
- 返回数据格式保持简单，优先满足文本问答

### 9.3 模块职责

- 首页模块：布局和模块编排
- 导航模块：卡片展示与导航数据操作
- 搜索模块：输入、模式切换、提交行为
- AI 模块：问答展示和会话最小上下文
- 设置模块：有限偏好项管理
- 存储模块：本地读写封装

## 10. 技术约束

### 10.1 技术栈

首版默认采用：

- Next.js
- TypeScript
- App Router
- Tailwind CSS

可选但非必需：

- shadcn/ui
- Framer Motion

首版不把以下内容设为必选：

- Three.js
- React Three Fiber
- 数据库
- 第三方状态管理库

### 10.2 工程约束

- 组件职责单一
- 文件命名语义清晰
- 避免超大页面文件
- API 逻辑放在 `app/api/*/route.ts`

## 11. 开发顺序

开发默认按以下顺序推进：

1. 初始化项目与全局样式变量
2. 搭建首页整体布局
3. 完成统一搜索框
4. 完成导航卡片区
5. 完成 AI 面板基础交互
6. 接入本地存储
7. 补设置入口与基础偏好
8. 补加载态、空状态、错误态
9. 做视觉统一和轻量动效打磨

如果出现范围冲突，以“先保证核心闭环能跑通”为准，不优先做华丽效果。

## 12. 验收标准

### 12.1 功能验收

满足以下条件即可认为 MVP 达标：

- 项目可在本地正常启动
- 首页可访问且结构完整
- 导航卡片可展示、跳转、基础持久化
- 搜索框支持 `web | ai | direct` 三种模式
- AI 面板可完成基础问答
- 默认偏好与轻量历史可持久化

### 12.2 体验验收

- 搜索框在首屏中足够突出
- 加载与错误反馈明确
- AI 回复区域排版可读
- 页面在普通桌面设备上流畅
- 手机端至少可完成搜索、跳转、提问

### 12.3 文档验收

README 应满足这些要求：

- 开发者只读本文件即可判断做什么、不做什么
- 不再出现大量重复愿景性章节
- 每个功能模块都包含职责、边界与验收点
- 数据对象和接口边界足够支撑实现起步

```bash
NEXT_PUBLIC_APP_NAME=MyWorld
OPENAI_API_KEY=
SEARCH_API_KEY=
SEARCH_API_BASE_URL=
```

约束如下：

- 所有密钥只在服务端使用
- 前端不得暴露供应商密钥
- 前端优先调用本项目接口

## 15. 开发原则

如果由 AI 编程助手或多人协作推进本项目，默认遵守以下原则：

- 优先完成 MVP，不擅自扩张范围
- 先保证结构和闭环，再优化特效
- 代码必须易读、可维护、可继续扩展
- UI 必须统一，不生成廉价模板风格界面
- 每个新增能力都要先判断是否属于 MVP

---

## 16. 当前结论

MyWorld 第一阶段不是“做一个很大的平台”，而是做一个 **你愿意每天打开使用的个人数字入口**。

开发时始终以这条判断取舍：

> 如果一个功能不能直接提升“打开即用”的效率与体验，就不应进入当前 MVP。
